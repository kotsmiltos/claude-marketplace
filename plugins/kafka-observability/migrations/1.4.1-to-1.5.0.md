# observability library 1.4.1 → 1.5.0

Coverage release: **opt-in backend HTTP call tracing**. New module `backend-trace.ts`
(+ `backend-trace.test.ts`), re-exported from `index.ts`: `traceBackendCall` executes an
outgoing backend HTTP call as a traced child run — named `http:<endpoint>`, tagged
`backend-http`, carrying `backend_endpoint` / `backend_base_url` / `backend_envelope` /
`backend_attempt` / `backend_max_attempts` / `backend_retryable` metadata — nested under
the node/tool run that issued it via LangChain's AsyncLocalStorage callback inheritance
(no `RunnableConfig` threading through the client's signature). `withAttemptContext` /
`currentAttempt` let a project's retry wrapper make each attempt a separate visible run.
Closes the one blind spot in an otherwise complete trace: what was sent to the backends
and what came back, durably, next to the LLM turns that decided to make the call.

Additive only: no export was removed or changed, no env key added (the helper rides
`KAFKA_ENABLED`), the event schema is untouched (HTTP runs flow through the existing
pipeline as ordinary runs). Nothing is traced until project code calls the helper —
**with no adoption, emitted bytes are identical to 1.4.1.**

**Security contract:** the library redactor is credential-only. `traceBackendCall`'s
`input` and `logged` values MUST be pre-masked by the project's own domain redaction —
these events land in a durable, indexed sink. See the library README, "Backend HTTP call
tracing", before wiring anything.

<transforms>

**1. No mandatory transforms.** Library file replacement only (the wholesale vendored
copy includes the two new files; `index.ts` re-exports arrive with it).
check: `grep -q "traceBackendCall" src/observability/index.ts` after vendoring.

**2. Conditional — a pre-1.5.0 hand-rolled equivalent exists.** Some projects shipped
this module at the project layer before the library did (a tool-local `trace.ts`
exporting `traceBackendCall` / `withAttemptContext`, wired into their backend client).
Detect: `grep -rln "traceBackendCall" src --include='*.ts' | grep -v observability`.
If found and its API matches the library's (same `TracedCallInfo` / `TracedCallOutcome`
shape):

1. Re-point the importing files (backend client, retry wrapper) from the local module
   to `src/observability/index.js` (or `../../observability/backend-trace.js` at the
   project's preferred depth).
2. Delete the local module — but NOT its tests if they assert the project's own
   redaction (those test the project's masking contract, which stays project-owned;
   update their imports instead).
3. `npx tsc --noEmit` must pass.

If the local API diverges, STOP and surface the diff to the user instead of forcing the
swap. check: after the swap, `grep -rln "traceBackendCall" src --include='*.ts'` outside
`src/observability/` shows only importers, no second definition.

**3. Advisory (not a transform): adopting from scratch.** Offer, don't apply silently —
wrapping the backend chokepoint is a project-code edit (see the install workflow Step 5,
optional item): wrap the single `postBackend`-style helper, run retry attempts inside
`withAttemptContext`, and FIRST audit the project's domain redaction against the real
backend response shapes (person-name spellings such as `customerName` / `shortName` /
`contactName` are commonly missed; a durable indexed sink forgives nothing a rotating
log file did).

</transforms>
