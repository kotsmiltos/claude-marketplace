# observability library 1.1.0 → 1.2.0

Attachment-robustness release (INC-2026-0045 root cause). `registerConfigureHook` — the
sole attachment path until now — stores its registry in AsyncLocalStorage, so a hook
registered at graph-module load never fires for runs whose async context does not descend
from `startup()` (observed on LangGraph Platform under Azure App Service: hook registered
at boot, zero tracer events ever). The library now attaches through two redundant,
name-deduped paths: the hook, plus a *configure-slot* wrap of the project's own
`CallbackManager._configureSync` — the same ancestry-independent attachment point
LangSmith's tracer occupies. Startup logs a one-line attachment diagnostic (core copy URL,
ALS presence, boot-visible hooks, `NODE_OPTIONS`), and an `ALS context break detected`
warning fires the first time the slot has to attach although the hook was registered.

Additive only: event schema, transport, wiring (`startup()` once at graph entry), and the
disabled-by-default contract are identical to 1.1.0. One new **optional** env var,
`KAFKA_ATTACH_MODE` (`hook` | `patch` | `both`, default `both`; invalid values throw at
startup).

<transforms>

**1. `.env.example` — document the new optional attach-mode var.**
Append to the existing Kafka observability block (immediately after the last `KAFKA_*`
line):

```
# Tracer attachment path: hook | patch | both (default both; see src/observability/README.md "Attachment")
# KAFKA_ATTACH_MODE=both
```

check: `grep -q "KAFKA_ATTACH_MODE" .env.example` — if it already matches, skip (idempotent).
Deployment settings files need **no** change: the default (`both`) is correct everywhere;
only set the var to pin a single path during diagnosis.

**2. Advisory (not a transform): retire temporary attachment probes.** Projects that
added project-level diagnostics for INC-2026-0045 (e.g. a configure-hook probe handler,
an emitRun-counting emitter wrapper wired via `setEmitter()`/`getEmitter()`) can remove
them after verifying in the target runtime that (a) the startup line
`[observability] attachment diagnostics:` appears and (b) real conversations produce
events. The library's own diagnostics now cover what the probes measured.

**3. Advisory (not a transform): log tooling.** Dashboards/alerts may want to watch for
`ALS context break detected` (tracer attached via fallback — runtime severs async
ancestry; worth escalating to the platform owner) and `duplicate library copy detected`.
Both are warnings, not errors — events still flow.

</transforms>
