# observability library 1.0.0 → 1.1.0

Connection-diagnostics release. The library now distinguishes "connected" from
"never connected" in its logs: the producer logs
`[observability] Kafka producer connected` when the broker handshake completes, a
one-shot 30 s watchdog warns (with the in-memory queue fill) when it never does, and the
startup line was reworded from "Kafka run tracing ready: …" to "Kafka run tracing
initialized (producer connecting in background): …" because at that point no
broker/SASL handshake has happened yet.

No behavior changes: `produce()`, drain, and shutdown semantics, config keys/env vars,
and the disabled-by-default contract are identical to 1.0.0.

<transforms>

**Pure file refresh — no project-level transforms.** No env vars were added or renamed,
no wiring changes, no deployment-settings migration. The wholesale replacement of
`src/observability/` that the skill always performs is the entire upgrade.

One advisory (not a transform): if any project-level tooling — log dashboards, alert
rules, smoke-test greps — matches the old startup line `Kafka run tracing ready`, update
it to match `Kafka run tracing initialized` (and consider alerting on the new
`has NOT connected` watchdog warning, which is the signal the old logs lacked).

</transforms>
