# observability library 1.6.0 → 1.7.0

Privacy release: **masking of digits spoken as words**. New primitive
`maskSpokenDigitsInText(text, opts?)` in `content-mask.ts` (re-exported from `index.ts`,
with `SpokenDigitLanguage` / `SpokenDigitMaskOptions`), plus an opt-in
`spokenLanguages: ["el", "en"]` option on `digitContentMask`.

Why: the 1.6.0 seam catches numerals, but callers on a voice channel *speak* — a live
Kafka capture of a full PIN-change conversation on a downstream voice agent showed zero
plaintext PIN/OTP numerals and yet carried the PIN as «τέσσερα οκτώ τρία επτά» (59
occurrences) and the OTP as «ένα δύο τρία τέσσερα πέντε έξι» (135 occurrences) in raw
caller utterances inside llm-run content. For voice, word-form is how digits normally
arrive — the dominant residual leak, not an edge case — and English word digits ("four
eight three seven") leak identically. This was the first limit named in the 1.5.0→1.6.0
guide; 1.7.0 closes it for word digits 0–9.

The rule, out loud (mirroring `maskDigitsInText`'s spirit): consecutive spoken digit
words joined by spaces, commas or dashes are one run («τέσσερα, οκτώ, τρία, επτά»);
numerals and already-masked `#` tokens inside the run count as members, so mixed
dictation («τέσσερα 8 τρία επτά») stays one run; a run is masked only at **minRun 3+**
members with at least one actual digit word — a lone «ένα» («θέλω ένα νέο PIN») or a pair
(«δύο τρία λεπτά») survives as prose, while PIN (4) and OTP (6) shapes are always caught.
One `#` per word, digit-for-digit for an embedded numeral, and **no last-N tail** —
word-form values are always secret-bearing (PINs, OTPs), never correlation identifiers a
flow reads back. Greek matching is case-insensitive and accent-tolerant («ΤΕΣΣΕΡΑ»,
«τεσσερα») and covers the spoken variants and inflections (ένα/μία/μια, δύο/δυο,
τρία/τρεις, τέσσερα/τέσσερις, επτά/εφτά, οκτώ/οχτώ, εννέα/εννιά, μηδέν, πέντε, έξι);
English is zero/oh/one…nine.

Additive only, same contract as 1.6.0: no export removed or changed, no env key (language
selection is a code option, masking stays code), event schema untouched, the
`events[].name`/`events[].time` carve-out stays. **With nothing new wired, emitted bytes
are identical to 1.6.0** — guarded by an emitter-level regression test pinning
`digitContentMask()` without `spokenLanguages` to spoken-words-verbatim output.

<transforms>

**1. No mandatory transforms.** Library file replacement only — the wholesale vendored
copy brings the new primitive and the `index.ts` re-exports.
check: `grep -q "maskSpokenDigitsInText" src/observability/index.ts` after vendoring.

**2. Optional — extend an existing masking policy with the spoken pass.** Nothing new is
masked until you do. Decide with the user; declining preserves 1.6.0 behaviour exactly.
This only applies where a `contentMask` is already wired (or is being wired now — do that
via `migrations/1.5.0-to-1.6.0.md`'s transform 2 first); for a voice-channel agent the
spoken pass is the point of this release and should be proposed, not buried.

**2a. The project wired `digitContentMask(...)`.** Add the option:

```ts
startupObservability({
  contentMask: digitContentMask({ keys: true, spokenLanguages: ["el", "en"] }),
});
```

**2b. The project composed its own domain masker with the digit primitives.** Wrap the
string pass — spoken pass AFTER `maskDigitsInText`, both still INSIDE the key-based
masker:

```ts
startupObservability({
  contentMask: (value) =>
    redactValue(
      mapStringsDeep(value, (s) => maskSpokenDigitsInText(maskDigitsInText(s)), { keys: true }),
    ),
});
```

Both orders are load-bearing. Key tiers trim tails and the digit pass preserves them
(unchanged from 1.6.0); and the numeral pass runs BEFORE the spoken pass because a
numeral inside a dictated run has already become `#` («τέσσερα 8 τρία» →
«τέσσερα # τρία») and the spoken pass counts `#` tokens as run members — reversed, a
mixed run splits into sub-minRun fragments and leaks every word.

Name the rule to the user the way 1.6.0's guide named the digit rule: runs of 3+ spoken
digit words (Greek + English packs) are masked one `#` per word with no tail; a lone
digit word in prose survives. If the agent's callers use only one language, a subset
(`["el"]` / `["en"]`) is valid — but both packs cost nothing and ASR sometimes
code-switches.

**3. Verify.** `npx tsc --noEmit`, then `npm run test:observability` (**194** tests, up
from 158). The startup line is unchanged (`content_mask=host|off`) — the spoken pass is
part of the host policy, not a new switch.

**4. Deployment.** Nothing to add: no env key, no secret, no Key Vault reference. The
language selection travels in the code.

</transforms>

## Remaining limits, stated explicitly

- **Number words above nine are out of scope**: composed forms like «σαράντα οκτώ» /
  "forty-eight" are a semantic parse this library does not attempt. A caller who dictates
  a PIN as «σαράντα οκτώ, τριάντα επτά» is not caught — only digit-by-digit dictation is.
- **Languages without a built-in pack** (anything beyond Greek and English) pass through
  untouched; the `languages` option selects among built-ins, it does not add packs.
- **Runs shorter than minRun leak by design**: a PIN fragment of 1–2 words separated from
  its run (e.g. by an ASR-inserted non-digit word) survives as prose. minRun 3 is the
  prose/secret trade-off, chosen so «θέλω ένα νέο PIN» keeps its «ένα».
- Everything 1.6.0 listed still holds: nothing is masked until a policy is wired,
  non-numeric PII needs key rules, and `metadata` is out of scope (no PII in
  `configurable`).
