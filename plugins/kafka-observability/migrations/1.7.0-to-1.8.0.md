# observability library 1.7.0 → 1.8.0

Parity release: **spoken digit runs now follow the numeral pass's length rule**. New
`keepLast` (default 4) / `keepLastMinRun` (default 7) options on `maskSpokenDigitsInText`,
mirroring `maskDigitsInText`'s options and defaults; the language packs now map each word
to its numeral so a kept tail can be translated.

Why: 1.7.0 masked every qualifying word run whole, claiming word-form values are never
correlation identifiers. Callers dictate card numbers and tax ids too — and those, typed
or ASR-recognized as numerals, keep the `***4410` / `***6789` tail the flow itself reads
back. Spoken, they lost it entirely: the same card shipped as `***4410` or as sixteen
`#`'s depending on nothing but whether the caller spoke or typed. The numeral pass's
length boundary discriminates the same shapes in word form — **7+ digits is a dictated
identifier** (card 16, ΑΦΜ 9) and keeps a translated `***<last4>`; **3–6 is a secret**
(PIN 4, OTP 6) and is masked whole, exactly as in 1.7.0.

The rule, updated out loud: a run of `keepLastMinRun`+ digits collapses whole (separators
included) to `***` + the last `keepLast` digits, kept words translated to numerals
(«…τέσσερα τέσσερα ένα μηδέν» → `***4410`); shorter runs stay one `#` per word,
digit-for-digit for embedded numerals. The tail is real or absent, never partial — if any
kept digit is unrecoverable (a `#` left by the prior digit pass in a mixed run), the run
is masked whole. minRun 3, the prose guard, the run-member rules and the language packs
are unchanged.

Additive API, one default-behaviour change to know: no export removed or changed, no env
key, event schema untouched, and everything unwired is untouched (no policy, or no spoken
pass in the policy → bytes still identical to 1.6.0, same regression guards). But **a
policy that already wired the spoken pass on 1.7.0 changes output for 7+-digit word
runs**: whole-mask → translated `***<last4>` tail. PIN/OTP output is byte-identical.
Projects that deliberately want the 1.7.0 whole-mask pass `keepLast: 0`.

<transforms>

**1. No mandatory transforms.** Library file replacement only. A project whose policy
calls `maskSpokenDigitsInText(...)` or `digitContentMask({ spokenLanguages })` without
`keepLast` options picks up parity through the file refresh alone — no wiring edit.
check: `grep -q "keepLastMinRun" src/observability/content-mask.ts` after vendoring.

**2. Decision point — tell the user about the default change, don't silently apply it.**
If the project wired the spoken pass on 1.7.0, state it plainly: dictated identifiers of
7+ digit words (cards, tax ids) now keep a translated last-four on the topic, matching
what the numeral pass already does for the typed form. Two valid answers:

- **Parity (recommended, the new default):** nothing to edit. Consistent with the
  project's existing numeral policy — if `***4410` is acceptable typed, it is acceptable
  spoken.
- **Keep 1.7.0's whole-mask:** pass `keepLast: 0` to the spoken pass (and note the
  asymmetry this preserves against the numeral pass, unless the numeral pass uses
  `keepLast: 0` too):

  ```ts
  // digitContentMask form — NOTE: keepLast: 0 blankets BOTH passes:
  contentMask: digitContentMask({ keys: true, spokenLanguages: ["el", "en"], keepLast: 0 })

  // manual composition form — spoken pass only:
  (s) => maskSpokenDigitsInText(maskDigitsInText(s), { keepLast: 0 })
  ```

**3. Verify.** `npx tsc --noEmit`, then `npm run test:observability` (**206** tests, up
from 194). Spot-check the wired policy: a 16-word dictated card must come out `***<its
real last four>`; the 6-word OTP must still be `# # # # # #`.

**4. Deployment.** Nothing to add: no env key, no secret, no Key Vault reference.

</transforms>

## Remaining limits, restated

- **Number words above nine stay out of scope** («σαράντα οκτώ», "forty-eight") — a
  caller dictating in composed pairs is caught by neither pass.
- **Languages beyond Greek/English** pass through untouched.
- **`keepLast: 4` now leaves four real digits of a dictated identifier** on the topic,
  same as the numeral pass always did for the typed form. That is the point — but it *is*
  four real digits; `keepLast: 0` removes them (blanketing both passes when set on
  `digitContentMask`).
- Sub-minRun fragments, non-numeric PII, and the `metadata`/`configurable` caveat: as in
  the 1.6.0→1.7.0 guide.
