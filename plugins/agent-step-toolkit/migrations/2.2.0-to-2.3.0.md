# Migrate agent-step 2.2.0 → 2.3.0

> Severity: additive. Applied by `/pull-library`; readable standalone.

## What changed

Six additive capabilities, no removals and no signature changes. Every one of them exists to **retire a
host workaround**, so the upgrade value is in the code you delete, not in the library swap.

- `HandoffSpec.forcedHandoff?(state)` + `forcedHandoffRequested(state, spec)` (new export) — a handoff
  derived from state when the MODEL ended a turn in plain text.
- `HandoffSpec.resolveHandoffType?(state, request)` — the handback SIGNAL decided from state.
- `HandoffSpec.resolveHandoffMetadata?(state, request)` — host fields merged into `handoff_metadata`.
- `guardTurn` slot + `guardFiredOnTurn` / `markGuardFired` — a turn-scoped latch for host model-input
  guards.
- `resolveCallerTurnId` (now exported) — the library's own "current caller turn" resolver.
- `ConfirmationOpts.readBack?(params, state)` → `read_back` on the proposal body.

```ts
// before — the forced handback as a host node that writes the library slot
.addNode("force_handback", (s) => ({ handoff: { reason: "abandon", context: closing(s) } }))
.addConditionalEdges("agent", (s) => taskIsOver(s) ? "force_handback" : END)

// after — no node, no slot write; predicate and resolver share one pure function
const spec: HandoffSpec<AgentState> = {
  ...,
  forcedHandoff: (s) => taskIsOver(s) ? { reason: "abandon", context: closing(s) } : undefined,
  clearsOnHandback: ["taskOutcome"],   // ← not optional in practice; see the trap below
};
.addConditionalEdges("agent", (s) => forcedHandoffRequested(s, spec) ? HANDOFF_NODE : END)
```

```ts
// before — reaching into the frozen envelope after the node built it
const msg = await resolveHandoff(state, config);
(msg.additional_kwargs.handoff_metadata as Record<string, unknown>).collected_identity = id(state);
msg.additional_kwargs.handoff_type = signalFrom(state);        // the `handoff` EVENT still says otherwise

// after — resolved inside the node, before the first control-plane event
resolveHandoffType: (s, r) => signalFrom(s),
resolveHandoffMetadata: (s, r) => { const c = id(s); return c ? { collected_identity: c } : undefined; },
```

## Why

Each of these was a boundary hosts were reaching around, and the workaround was worse than the gap.
Overriding the signal by mutating `additional_kwargs` after the fact left the `handoff` control-plane
event carrying the PRE-override reason — a streaming client rerouted on one value while the envelope
said another. Forcing a handback from a host node meant host code writing the library-managed `handoff`
slot that 2.0.0 explicitly put off-limits to everyone else. Re-deriving the caller turn by scanning the
transcript backwards produced a second, subtly different definition of "turn" than the one the
confirmation gate enforces — and hosts then parked the answer inside that same frozen envelope. And
leaving the model to paraphrase captured digits back to the caller is measurably where read-backs break:
a model converting digits to words drops or doubles one on runs of equals, and the caller confirms
against wrong words — the one mistake a confirmation gate cannot catch.

## Library replacement

The vendored `src/agent-step/*` is replaced wholesale by `/pull-library` (verbatim copy from the
toolkit; recursive). **Two files are added**: `interaction/guard-latch.ts` and the top-level
`guard-latch.test.ts`. The suite grows 173 → 193 (5 forced-handoff, 3 metadata, 5 `readBack`, 7 latch).

A project that adopts none of these hooks needs no change beyond the copy — every addition is optional
and every default preserves the pre-2.3.0 behaviour.

   target: the project's state module (typically `src/state.ts`).

   target: any host node or conditional edge that FORCES a handback by writing the library `handoff`

     `{ handoff: { reason, context } }` guarded by a "task is already over" predicate.
   change: Move the predicate's body into `spec.forcedHandoff: (state) => HandoffRequest | undefined`

     conditional edge through `forcedHandoffRequested(state, spec) ? HANDOFF_NODE : END`. Keep it a
     PURE function of state — it runs on turns where the model answered in plain text, so it cannot
     read the caller's words. Then, in the SAME edit, add every terminal slot it reads to
     `clearsOnHandback` (see the check — this is not optional in practice).
   example: |
     - .addNode("force_handback", (s) => ({ handoff: { reason: "abandon", context: closing(s) } }))
     - .addConditionalEdges("agent", (s) => taskIsOver(s) ? "force_handback" : END)
     + forcedHandoff: (s) => taskIsOver(s) ? { reason: "abandon", context: closing(s) } : undefined,
     + clearsOnHandback: ["taskOutcome"],
     + .addConditionalEdges("agent", (s) => forcedHandoffRequested(s, spec) ? HANDOFF_NODE : END)
   check: `npm run typecheck` passes and no host code writes the `handoff` slot any more
     (`grep -n "handoff:" src/ --include=*.ts` outside `src/agent-step/` should show only the spec).

     again on the same thread — must NOT re-fire it. If it does, the slot the predicate reads is

3. id: adopt-resolve-handoff-type
   target: any code that overrides `handoff_type` / `handoff_metadata.service_type` AFTER
     `createHandoffNode` resolved — a wrapper around the `resolve_handoff` node mutating the returned
     message's `additional_kwargs`.
   change: Replace it with `spec.resolveHandoffType: (state, request) => "completed" | "abandon" |
     undefined`, returning `undefined` to fall through to the model's reason. Delete the wrapper's
     mutation. Note the scope: the hook is consulted only for a terminate-mode `completed`/`abandon` —
     never `off_topic`, never a successful delegate — so any override logic that tried to rewrite
     those cases was already inert and should be dropped rather than ported.
   check: the `handoff` custom event's `reason` and the final message's `handoff_type` carry the SAME
     value on a run that exercises the override (they diverged before this change).

4. id: adopt-resolve-handoff-metadata
   target: any code adding host fields to `handoff_metadata` from outside — e.g.
     `(md as Record<string, unknown>).collected_identity = …` in a resolve-handoff wrapper.
   change: Replace it with `spec.resolveHandoffMetadata: (state, request) => Record<string, unknown> |
     undefined`. Return `undefined` when there is nothing to add. Do NOT return `service_type` or
     `success_message` — the library applies its own keys last and yours would be discarded. Remember
     it is called for `off_topic` too, which is usually what you want for identity forwarded to a
     call-scoped store.
   check: the wrapper no longer touches `additional_kwargs`; a handback run still carries the host
     fields, and a deliberately conflicting `service_type` in the hook's return does not appear.

5. id: adopt-guard-latch
   target: any host model-input guard that must fire once per caller turn — typically a nudge or note
     injected in the agent node, latched by scanning `state.messages` backwards for the latest human
     message id, or by a marker stored in a message's `additional_kwargs`.
   change: Replace the hand-rolled latch with `guardFiredOnTurn(state, "<guard-id>", getCallerTurnId?)`
     to test and `markGuardFired(state, "<guard-id>", getCallerTurnId?)` to record, merging the returned
     patch into the node's return value. Delete any host re-derivation of the caller turn in favour of
     the exported `resolveCallerTurnId`, and pass the SAME `getCallerTurnId` the project gives
     `buildAgentStepTool` (or omit it in both places) so the halves agree on where a turn starts.
     CRITICAL when a node fires more than one guard: the patches do NOT compose by spreading — each
     carries a whole `guardTurn` map built from the state passed in and the reducer replaces, so
     `{...markGuardFired(s,"a"), ...markGuardFired(s,"b")}` silently loses `"a"`. Merge the maps by
     hand or thread the state forward.
   check: `npm run typecheck` passes; a sandbox turn that re-enters the model several times injects the
     note exactly ONCE, and the next caller turn re-arms it.

6. id: adopt-confirmation-read-back
   target: OPTIONAL but strongly recommended — any confirm-gated action whose params carry
     caller-dictated digits (tax numbers, card-number tails, amounts), plus the prompt section that
     tells the model how to recap a proposal.
   change: Add `readBack` to that action's `requiresConfirmation` opts, rendering the stored params in
     the caller's language (a host module — the library owns the capture, not the lexicon; cast the
     state parameter to your own state type as executors do with their slices). Then change the prompt
     rule from "recap the proposed params" to "when the result carries `read_back`, speak it VERBATIM"
     — without that rule the field is inert and the model keeps paraphrasing.
   check: a propose-turn tool result carries `read_back`; a re-proposal carries a fresh one rendered
     from the corrected params; the executing re-call carries none.
</transforms>

## Manual follow-ups

1. **Read-back wording is host-owned and QA-gated.** The library deliberately supplies no default: the
   phrasing is language- and channel-specific and the whole point is that it matches what the caller
   will hear. Have it reviewed like prompt text, not like a helper.
2. **`forcedHandoff` adoption is a state-hygiene change, not a wiring change.** Before enabling it, list
   every slot the predicate reads and confirm each one is either in `clearsOnHandback` or genuinely
   call-scoped (a verified customer, the caller's language). Slots whose reducer MERGES cannot be
   cleared this way — reset those through the pointer slot that selects from them.
3. **Deciding the signal from state changes what the middleware routes on.** `resolveHandoffType` can
   turn a model-declared `completed` into `abandon`. Confirm the routing table treats both the way you
   expect for this agent before relying on it.
4. **No middleware change is required by any of this.** The wire contract is unchanged: the same
   `is_handoff` / `handoff_type` / `handoff_reason` / `handoff_metadata` shape, now assembled in one
   place instead of patched afterwards.
