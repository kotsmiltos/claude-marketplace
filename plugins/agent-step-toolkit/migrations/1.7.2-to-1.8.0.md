# Migrate agent-step 1.7.2 → 1.8.0

> Severity: additive surface + behavior deltas (confirm gate, invalidation cascade, auto-handoff
> instruction). Applied by `/pull-library`; readable standalone.

## What changed

All additive at the type level (no export removed, no signature changed):

- **Confirm gate compares schema-NORMALIZED params.** New internal `paramsMatchPending` parses the
  raw re-call with the action's effective schema before comparing (deep value equality) against the
  stored PARSED proposal; a failed parse counts as drift. The propose branch parses with the same
  schema. Re-calls that normalize to the stored proposal now EXECUTE (previously any
  value-normalizing schema — e.g. a `z.preprocess` stripping STT separators — made them read as
  drift: re-propose loop → attempts exhausted without ever executing).
- **Propose-path `invalid_params` is voice-safe.** The summary is the overridable `invalid_params`
  system message; raw Zod detail moves to `_debug` (matching the execute path).
- **17 new templated `SystemMessages` keys** (lockdown / batch-shape / confirmation / OTP / match
  gate summaries, `handoff_requested`, `no_steps`, `auto_handoff_instruction`) with `{placeholder}`
  interpolation via a new `formatMessage` helper. Every runner-emitted summary is now overridable.
  Defaults preserve the previous hardcoded strings, except:
- **The auto-handoff instruction defaults to platform-delivers wording.** The synthetic
  `auto_handoff` result's summary no longer says `Speak this exact message to the caller: "…"`; it
  now says the turn ends here, produce no further answer — the platform delivers the closing.
  Override `auto_handoff_instruction` (placeholder `{message}` = the `auto_handoff` closing) to
  restore the old behavior.
- **`invalidatesOnChange` uses deep value equality** (canonicalized JSON) instead of `Object.is` —
  a fresh-but-value-equal OBJECT re-write no longer fires a spurious cascade. New `types.ts`
  caveat: invalidation targets must be replace-on-write slots.
- **`HandoffSpec.actionDescription`** (optional) — override the LLM-facing description of the
  auto-injected `request_handoff` schema variant.

## Why

Absorbed from a downstream voice agent. Confirmation gating with value-normalizing param schemas
was impossible (the blocking defect above); `Object.is` change detection fired invalidation
cascades on every object re-write; localized/voice hosts could not reach the most frequent runner
summaries (lockdown and confirmation refusals); and the auto-handoff "speak this" instruction
double-spoke on hosts whose graph or middleware already delivers the closing — which is both
wiring paths the toolkit teaches.

## Manual follow-ups

1. **Decide who delivers the auto-handoff closing.** If the graph wires `createHandoffNode` (or a
   middleware speaks `handoff_metadata.success_message`), the new default is correct — the model
   stays silent, the platform speaks. If NEITHER delivers it (e.g. a bare `onErrorThreshold`
   writing a custom slot with no speaking mechanism), the caller now hears silence at the
   threshold — override the template:
   ```ts
   buildAgentStepTool({ …, messages: {
     auto_handoff_instruction:
       'Speak this exact message to the caller: "{message}" Then stop.',
   }});
   ```
2. **Re-run confirm-gated sandbox flows.** Behavior delta: a re-call whose params normalize to the
   stored proposal now EXECUTES (previously re-proposed). Tests that asserted a re-propose for
   separator/format artifacts must now expect execution.
3. **Adopt localized summaries (optional).** Hosts that override `messages` for voice/locale can
   now reach all 26 runner summaries — map the new keys (see `<system_messages>` in
   `agent-step-api.md`) into the existing override block; `{placeholder}` tokens interpolate at
   emit time and overrides can live in JSON locale resources.
4. **`request_handoff` schema honesty (optional).** If `resolveClosingMessage` composes every
   closing from state, set `HandoffSpec.actionDescription` so the model isn't told its `context`
   gets spoken.
