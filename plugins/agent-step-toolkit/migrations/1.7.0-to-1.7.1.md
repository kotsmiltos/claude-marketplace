# Migrate agent-step 1.7.0 → 1.7.1

> Severity: internal (library) + contract fix (the `AgentInputSchema` recipe). Applied by
> `/pull-library`; readable standalone.

## What changed

The **recommended `AgentInputSchema` derivation re-attaches `messages` after `.partial()`** so
LangGraph Studio keeps rendering its chat input box. Nothing in the vendored runner changed —
`src/agent-step/*` is byte-identical to 1.7.0. The fix is purely in how a project derives its graph
INPUT schema from `AgentStateSchema`.

```ts
// Before (1.7.0): .partial() runs over messages too.
export const AgentInputSchema = AgentStateSchema.omit({
  ...agentStepInternalSlotMask,
  pendingHandoff: true,   // + any other executor-written / derived slot
}).partial();

// After (1.7.1): re-attach messages from its native shape after .partial().
export const AgentInputSchema = AgentStateSchema.omit({
  ...agentStepInternalSlotMask,
  pendingHandoff: true,
})
  .partial()
  .extend({ messages: MessagesZodState.shape.messages });
```

`MessagesZodState` is already imported in `state.ts` (it is the base of
`AgentStateSchema = MessagesZodState.extend({...})`), so no new import is needed.

## Why

`.partial()` makes every field optional AND, for `messages`, strips the messages-channel metadata
that LangGraph Studio keys off to decide the input is a chat thread. With that metadata gone, the
served input schema still has a `messages` key but Studio can't recognise it as a messages array, so
it drops the chat input box and falls back to the raw-state editor ("pass new messages as state").
Re-attaching `messages` from `MessagesZodState.shape.messages` keeps it typed-and-required with its
native channel metadata, while the caller-supplied identity fields remain optional. This only
matters once `AgentInputSchema` is wired into a hand-built `StateGraph` (the `createReactAgent`
scaffold takes no separate `input` schema) — but fixing the exported schema is harmless either way.

## Library replacement

`/pull-library` replaces `src/agent-step/*` wholesale (verbatim copy from the toolkit). For this
release that copy is a **no-op** — the 1.7.1 runner files are identical to 1.7.0. The upgrade payload
is the transform below; the VERSION bump (1.7.0 → 1.7.1) is what makes `/pull-library` run it.

<transforms>
1. id: reattach-messages-to-agentinputschema
   target: `src/state.ts` (the exported `AgentInputSchema`)
   change: If `AgentInputSchema` is derived as `AgentStateSchema.omit({...}).partial()` and does NOT
     already chain `.extend({ messages: ... })`, append `.extend({ messages: MessagesZodState.shape.messages })`
     to the end of the chain (after `.partial()`). Confirm `MessagesZodState` is imported from
     `@langchain/langgraph` — it almost always already is, because `AgentStateSchema` is
     `MessagesZodState.extend({...})`; add the import only if it is missing. Idempotent — skip the
     file if `AgentInputSchema` already re-attaches `messages` (the chain already contains
     `.extend({ messages:` / `MessagesZodState.shape.messages`).
   example: |
     - export const AgentInputSchema = AgentStateSchema.omit({
     -   ...agentStepInternalSlotMask,
     -   pendingHandoff: true,
     - }).partial();
     + export const AgentInputSchema = AgentStateSchema.omit({
     +   ...agentStepInternalSlotMask,
     +   pendingHandoff: true,
     + })
     +   .partial()
     +   .extend({ messages: MessagesZodState.shape.messages });
   check: `grep -n "MessagesZodState.shape.messages" src/state.ts` returns the `AgentInputSchema`
     block; typecheck passes.
</transforms>

## Manual follow-ups

1. **Verify the chat box in Studio.** If the project hand-builds its graph with
   `new StateGraph({ state, input: AgentInputSchema })`, restart the dev server and confirm Studio
   shows the message input box (not "pass new messages as state"). Projects on `createReactAgent`
   were never affected (no separate `input` schema is served), but applying the transform keeps the
   exported schema correct for the day they graduate to a hand-built `StateGraph`.
