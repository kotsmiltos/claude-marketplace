# Migrate agent-step 1.4.0 → 1.5.0

> Severity: additive + behavior note. Applied by `/pull-library`; readable standalone.

## What changed

Three additive surfaces and two flow-control hardenings (no breaking signature change):

- **New library file `messages.ts`** — the runner's own refusal/error `summary` strings (executor
  crash, invalid params, unknown action, abort, the flow gates) now come from
  `DEFAULT_SYSTEM_MESSAGES` (neutral English) and are overridable per-host:
  ```ts
  buildAgentStepTool({ /* … */, messages: { executor_error: "…", invalid_params: "…" } });
  ```
  `messages` is `Partial<SystemMessages>`, shallow-merged over the defaults. Exports added to
  `index.ts`: `SystemMessages`, `DEFAULT_SYSTEM_MESSAGES`, `resolveSystemMessages`.
- **`_debug` on error step results** — `executor_error` / `invalid_params` results now also carry a
  `_debug` field with the raw technical cause, so the (now overridable, user-safe) `summary` no
  longer has to leak backend internals.
- **`HandoffSpec.resolveClosingMessage?(state, request)`** — optional hook to override the
  `completed` / `abandon` closing line from actual operation outcomes (honesty invariant). Returns a
  string to replace the LLM-composed `request.context`, or `undefined` to fall through. Never called
  for `off_topic`.
- **Behavior — double-entry match frozen to batch start.** A `requiresMatch` consumer is now gated on
  the awaiting-input snapshot *at batch start*, not the live in-batch view. A capturer + its consumer
  in the SAME batch is refused (`match_not_pending`); the second entry must arrive in a separate turn.
- **Behavior — match-then-OTP ordering.** An `issuesOtp` step is refused (`otp_blocked_match_pending`,
  pre-execution) while a double-entry match gate is still pending.

## Why

`messages.ts` lets a localized / voice-safe agent (e.g. a TTS agent in another language) phrase the
runner's own system summaries without the library ever depending on a host file — and `_debug` keeps
the diagnostic detail out of the spoken text. `resolveClosingMessage` lets a flow speak a success
closing only when state proves the mutation persisted. The two gating guards close a real hole: a
single batch like `[capture_pin, commit_pin]` or `[capture_pin, request_otp]` could previously bypass
or overwrite the second-entry / match gate — a double-entry re-affirmation must span turns to be real.

## Library replacement

The vendored `src/agent-step/*` is replaced wholesale by `/pull-library` (verbatim copy from the
toolkit), which **adds the new `messages.ts`** file. No consumer code change is required for the
upgrade itself — the new APIs are opt-in and the guards are runtime. Test suite grows 79 → 83.

## Manual follow-ups

1. **Audit single-turn double-entry / OTP batches (REQUIRED if the project has a match flow).** Any
   tool or test that emitted a capturer and its `requiresMatch` consumer in ONE batch, or a capturer
   and an `issuesOtp` step in one batch, now refuses (`match_not_pending` / `otp_blocked_match_pending`).
   Split them across turns: capture → (separate turn) consume; consume the match → (same or later
   turn) issue the OTP. Update the prompt's flow narrative and any sandbox tests that threaded these
   in a single `runSteps` call.
2. **Optional — localize runner summaries.** For a non-English or voice agent, pass `messages` to
   `buildAgentStepTool` with voice-safe wording for the keys you care about (`executor_error`,
   `invalid_params`, `unknown_action`, `flow_already_active`, `no_flow`, `wrong_flow`, `abort_done`,
   `abort_nothing`). Leave unset to keep the English defaults.
3. **Optional — honest handback closings.** For a specialized agent using the library handoff, set
   `spec.resolveClosingMessage` so `completed` speaks the success line only when the state shows the
   operation persisted, else a neutral phrasing.
