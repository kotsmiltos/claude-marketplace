# Migrate agent-step 2.3.0 → 2.4.0

> Severity: additive. Applied by `/pull-library`; readable standalone.

## What changed

One additive capability, no removals and no signature changes: the **`deflect_aside` control** — a
damper for the trigger-happy `off_topic` handoff on a social aside mid-task. Without the opt-in the
model-facing surface is **byte-identical to 2.3.0** — the control is inactive and registered last,
so the established schema variants keep their injection order.

- `HandoffSpec.deflectAside?: boolean | { actionDescription?: string }` — opt-in; requires the
  handoff by construction (the repeat path escalates into it). The object form's
  `actionDescription` replaces the LLM-facing schema-variant description (the same override seam
  `request_handoff` has) so a host states its own classification policy.
- New task-scoped, library-managed slot `deflectedAside` — arrives with `agentStepZodShape` /
  `agentStepStateSpec`; `agentStepInternalSlotMask` grows **7 → 8 keys**; in
  `agentStepTaskScopedSlots` (a task-ENDING handback clears it; an `off_topic` roundtrip
  deliberately does NOT re-arm the freebie) and in the runner's `stateUpdate` ownership guard.
- New exports `DEFLECT_ASIDE_ACTION`, `DEFLECT_ASIDE_ACTION_DESCRIPTION`; new
  `SystemMessages.aside_deflected` key (model-facing instruction; host-overridable).
- New exclusivity group `deflect` (`deflect_must_be_sole_step`); `deflect_aside` is a reserved
  action name ONLY when enabled.

Behaviour when enabled:

```ts
// FIRST use in a task — no handoff. The latch is set, every pending gate/flow survives,
// and the result instructs the model (msgs.aside_deflected) to decline in ONE sentence
// and repeat its pending question in the SAME turn.
// REPEAT in the same task — atomic escalation into the off_topic handback, with the
// aside as the routing `context`. One-shot, like the bounded-choice overlay.
const spec: HandoffSpec<AgentState> = {
  ...,
  deflectAside: true,                        // or { actionDescription: "<the fleet's own policy>" }
};
```

## Why

An aside NO configured agent serves (weather, small talk) was handed off `off_topic` on the FIRST
utterance: the caller was re-routed to an agent that answers the aside no better, and the pending
task dangled. The re-route buys the caller nothing but a lost turn. The classification stays with
the model (a topic another configured agent may serve is still a real `off_topic`); the POLICY —
one free in-place deflection per task, then a deterministic escalation — is now engine-owned.
Misclassification is benign in both directions: a wrongly deflected in-scope ask hands off one turn
later on persistence; chit-chat wrongly sent through `request_handoff` is exactly the pre-2.4.0
behaviour.

## Library replacement

The vendored `src/agent-step/*` is replaced wholesale by `/pull-library` (verbatim copy from the
toolkit; recursive). **Two files are added**: `controls/deflect-aside.ts` and the top-level
`deflect-aside.test.ts`. For a project that does not opt in, the library replacement IS the whole
upgrade — the control stays inert and nothing else changes.

<transforms>

## Manual follow-ups

Adoption is **opt-in** and is prompt work as much as config work:

- Set `deflectAside: true` — or `deflectAside: { actionDescription: "…" }` to state the fleet's own
  classification policy in the model's terms — on the `HandoffSpec` passed to `buildAgentStepTool`.
- Teach the prompt the split the control depends on: a topic ANOTHER configured agent may serve (or
  a request for a human) still goes to `request_handoff` with `off_topic`; only chit-chat NO agent
  serves goes to `deflect_aside`; questions about the current task are just answered. Also teach
  the decline-and-re-ask turn shape the `aside_deflected` instruction asks for.
- Pin both sides of the split with prompt-input tests (one utterance another agent serves → expect
  `request_handoff`; one nobody serves → expect `deflect_aside`, then the same-turn re-ask).
- If the agent overrides `SystemMessages` wholesale for localization, add an `aside_deflected`
  override in the project's language (the default is neutral English; overrides are
  `Partial<SystemMessages>`, so omitting it just keeps the default).
