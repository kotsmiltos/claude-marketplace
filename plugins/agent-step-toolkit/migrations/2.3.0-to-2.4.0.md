# Migrate agent-step 2.3.0 → 2.4.0

> Severity: additive. Applied by `/pull-library`; readable standalone.

## What changed

One new injected control, `deflect_aside`, and the state + config surface it needs. Nothing is removed
and no signature changes. The control is **opt-in**: a project that does not set `deflectAside` on its
`HandoffSpec` gets a byte-identical model-facing surface to 2.3.0.

- **`HandoffSpec.deflectAside?: boolean`** — opt into the control. Requires handoff (the repeat path
  escalates into it).
- **`deflect_aside` action** (`controls/deflect-aside.ts`), params `{ aside: string }` — handle a
  NON-BANKING aside mid-task without ending the task.
- **`deflectedAside` slot** — the task-scoped one-shot latch the control owns.
- **`msgs.aside_deflected`** — the model-facing instruction returned on the free deflection.
- **`DEFLECT_ASIDE_ACTION` / `DEFLECT_ASIDE_ACTION_DESCRIPTION`** exported from `index.ts`.

The policy is engine-owned; only the CLASSIFICATION stays with the model:

```ts
// FIRST use in a task — no handoff. Latch set, every pending gate untouched.
{ action: "deflect_aside", ok: true, summary: msgs.aside_deflected, deflected: true }

// SECOND use in the same task — the free deflection is spent. The control applies the SAME
// requestHandoffPatch the handoff control applies, atomically, with the aside as routing context.
{ action: "deflect_aside", ok: true, deflect_exhausted: true, handoff_requested: true,
  reason: "off_topic" }
```

The control leads locked batches like the handoff does (`allowedDuringGateLockdown`,
`allowedDuringChoicePending`) — the whole point is a mid-gate aside, so the pending confirmation, OTP
or match gate must survive the deflection untouched. It is sole-step (`deflect` exclusivity group,
`deflect_must_be_sole_step`): a domain step in the same batch would mean the model both deflected the
caller AND advanced the flow, on a turn where the caller did not answer the pending question.

## Why

Measured on a QA voice session: a weather aside mid-identification was handed off `off_topic` on the
FIRST utterance. The caller was re-routed to the general agent — which neither answered the weather nor
offered to resume — and the in-progress task dangled. For NON-banking chit-chat, something no agent in
the fleet serves, the re-route buys the caller nothing but a lost turn and a dropped question. The
failure mode is cross-cutting: every specialized agent that hands back on off-topic has it.

The split that matters is not "on-topic vs off-topic" but **"can any agent serve this?"**. A banking
topic outside this agent's specialty must still hand back immediately — another agent serves it, and
answering it keeps the caller with the wrong agent. Chit-chat has no server anywhere, so the correct
answer is to decline it in place and steer back. That distinction needs the caller's words, so it stays
with the model; what happens next — one free pass, then a deterministic re-route — does not, so it moves
into the engine.

Misclassification is benign in both directions, which is why the split is safe to leave to the model: a
banking ask wrongly deflected hands off one turn later on the caller's persistence, and chit-chat
wrongly sent through `request_handoff` is exactly the pre-2.4.0 behaviour.

## Library replacement

The vendored `src/agent-step/*` is replaced wholesale by `/pull-library` (verbatim copy from the
toolkit; recursive). **Two files are added**: `controls/deflect-aside.ts` and the top-level
`deflect-aside.test.ts`. The suite grows 193 → 200 (opt-in gating, latch + gate survival, atomic
escalation carrying the aside as context, task-scoped clearing, sole-step enforcement, invalid params).

A project that does not opt in needs no change beyond the copy: `activeWhen` keeps the action out of the
model's schema entirely, so the tool surface, the injected description block and every existing test are
unchanged.

## Manual follow-ups

1. **The decline wording is host-owned.** `msgs.aside_deflected` is a MODEL-facing instruction, not
   caller-audible text — the library deliberately ships no refusal sentence. The one line the caller
   hears is composed by the model from the prompt, so review it like prompt text: one sentence, no
   details, no promises, and the pending question straight after it in the same turn.
2. **The latch is task-scoped, and an `off_topic` resolution does NOT clear it.** That is deliberate: a
   mid-task aside roundtrip that comes back must not re-arm the freebie. A task-ENDING handback clears
   it through `agentStepTaskScopedSlots`, so the next task on a middleware-reused thread gets its own
   free deflection. If you want per-call rather than per-task semantics, do not try to get there by
   editing the slot from host code — the runner owns it.
3. **One free pass is a policy choice, not a tuning knob.** The count is fixed in the engine on purpose:
   it is what makes the escalation deterministic rather than a matter of how persuasively the prompt
   describes patience. If an agent genuinely needs a different shape — a fork offered to the caller
   rather than a refusal — that is the bounded-choice overlay, not this control.
4. **No middleware change is required.** The escalation path applies the same `requestHandoffPatch` as
   `request_handoff`, so the wire contract is unchanged: an escalated deflection is indistinguishable
   from a model-emitted `off_topic` handback on the wire, aside as `context`.
