# Migrate agent-step 1.5.0 → 1.6.0

> Severity: additive + behavior note. Applied by `/pull-library`; readable standalone.

## What changed

An **auto-handoff safety net**, a **silent off_topic hand-back**, and **split delegate timeouts** —
all additive at the type level (no signature removed/changed).

- **Auto-handoff.** The runner keeps a consecutive backend-failure counter in a new library-managed
  `errorCount` slot and auto-triggers a handoff at a threshold. Three new opt-in
  `BuildAgentStepToolOptions`:
  ```ts
  backendFailureCodes?: string[];   // executor verdicts that count (executor_error always counts)
  errorHandoffThreshold?: number;   // default 3
  onErrorThreshold?: (update, state) => void;  // inject a custom handoff signal at the threshold
  ```
  At the threshold the runner writes the library `handoff` slot (`{ reason: "abandon", context:
  messages.auto_handoff }`) when `handoff` is enabled, and/or calls `onErrorThreshold`, resets the
  counter, and appends a synthetic `{ action: "auto_handoff", isHandoff: true, … }` result. The
  whole mechanism is **inert** unless a handoff path is configured. New `SystemMessages.auto_handoff`
  for the spoken line.
- **Silent off_topic.** `createHandoffNode` now emits **empty** spoken content for `off_topic`
  (`success_message: ""`) instead of `terminateMessage`; `terminateMessage` remains the
  delegate-FAILURE fallback. `completed` / `abandon` unchanged.
- **Delegate timeouts split** into `connectTimeoutMs` (default 10s) + `timeoutMs` (streaming,
  default 20s; was a single 60s).

## Why

Multiple downstream agents independently grew the same "hand off after N backend failures" feature,
each hard-coding its own project's verdict codes into the library. This release lifts that feature
into the library in a **host-configurable** form — the library bakes in
no domain codes (only the generic `executor_error` always counts). Silent off_topic reflects that a
topic change is an agent-to-agent re-route the *destination* agent narrates, not the source.

## Library replacement

`/pull-library` replaces `src/agent-step/*` wholesale (verbatim copy from the toolkit). The new
`errorCount` slot arrives automatically via the `agentStepStateSpec` / `agentStepZodShape` spreads
already in the project's `state.ts` — no per-slot edit needed. The auto-handoff feature stays inert
until the project opts in (transforms below are how a project opts in / de-contaminates a
hand-rolled version it had locally).

<transforms>
1. id: adopt-auto-handoff-config
   target: each tool's `index.ts` (the `buildAgentStepTool({ … })` call) that wants auto-handoff
   change: If the project previously hand-edited the vendored runner to hard-code backend-failure
     codes, REMOVE that edit (the library is now generic) and instead pass the codes as options:
     add `backendFailureCodes: [<the project's backend/network verdict codes>]` and, if it used a
     non-default threshold, `errorHandoffThreshold: <n>`. Leave `executor_error` OUT of the list —
     it always counts. Only list TRUE backend/network failures, never user-mistake / business-logic
     verdicts.
   example: |
     buildAgentStepTool({ config, stateAnnotation, selectors, executors, verifiers,
       handoff: handoffSpec,
       backendFailureCodes: ["service_error"],   // was hard-coded in runner.ts before
     });
   check: `grep -rn "BACKEND_FAILURE_CODES" src/agent-step/` returns nothing (no hand-edited list
     survives in the vendored library); typecheck passes.

2. id: move-runner-system-messages-to-override
   target: any project whose vendored `src/agent-step/runner.ts` imported a project file for system
     `summary` strings (e.g. `import { VOICE_MESSAGES } from "../voice-messages.js"`) — i.e. a
     project that skipped the 1.5.0 `messages.ts` decoupling
   change: The replaced runner no longer imports host strings. Pass them via the `messages` option
     instead: map the project's system-message block (including the new `auto_handoff` key) into a
     `Partial<SystemMessages>` and add `messages: { … }` to `buildAgentStepTool`. Keep the project's
     own message module for its EXECUTOR strings; only the runner's `summary` strings move to the
     option.
   example: |
     buildAgentStepTool({ …, messages: {
       executor_error: VOICE.system.executor_error,
       invalid_params: VOICE.system.invalid_params,
       auto_handoff:   VOICE.system.auto_handoff,
       // …the rest of SystemMessages…
     }});
   check: `grep -rn "voice-messages\|VOICE_MESSAGES" src/agent-step/` returns nothing; typecheck
     and tests pass.

3. id: split-batches-for-restored-guards
   target: any project that branched off 1.4.0 and never got the 1.5.0 match/OTP guards (tools/tests
     and prompt flow narrative)
   change: The 1.5.0 guards return on pull — a double-entry `requiresMatch` capturer and its
     consumer can no longer share a batch, and an `issuesOtp` step is refused while a match is
     pending (`otp_blocked_match_pending`). Split any single-turn batch that paired them across
     turns, and update the prompt flow narrative accordingly. (No-op for projects already on 1.5.0.)
   check: sandbox tests for the match / OTP flow pass; no `match_not_pending` /
     `otp_blocked_match_pending` on the legitimate path.
</transforms>

## Manual follow-ups

1. **off_topic now silent.** If a specialized agent relied on the off_topic handback *speaking*
   `terminateMessage`, that text is no longer spoken (it's now only the delegate-failure fallback).
   The destination/orchestrator owns the caller-facing reply on a topic change. Re-listen to one
   off_topic turn to confirm the UX is what you want; keep `terminateMessage` set (it still backs
   delegate failures).
2. **Tune `errorHandoffThreshold` / `backendFailureCodes`.** The default threshold is 3 and only
   `executor_error` counts out of the box. Decide which of your executors' `ok:false` verdicts are
   true backend/network failures and list them — be conservative (never list recoverable user
   errors).
3. **Custom (non-library) handoff mechanism.** If the project routes handoffs through a scaffold
   `pendingHandoff` slot rather than the library `handoff` opt, implement `onErrorThreshold` to
   write that slot at the threshold (the auto-handoff is inert otherwise).
