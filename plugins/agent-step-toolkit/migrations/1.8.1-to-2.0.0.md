# Migrate agent-step 1.8.1 → 2.0.0

> Severity: breaking. Applied by `/pull-library`; readable standalone.

## What changed

**The executor contract is reshaped around typed effects, and the runner is restructured into phase
modules.** Runtime semantics for existing flows are otherwise 1.8.1's, and the model-facing tool
surface (name + description + provider JSON schema) is byte-identical — the breaks are all in the
tool-authoring contract and the test-harness expectations. The release also absorbs two additive
capabilities: the **bounded-choice overlay** and the **caller-turn identity** hook, plus a hardening
round of turn-provenance guards (one of which — the confirmation same-turn lock — changes how
confirm-gated tests must be written).

The complete break list:

1. **`ExecutorResult` reshape.** `lifecycle` and `flowData` are GONE; both are typed entries in the
   new optional `effects: ExecutorEffect[]`:
   ```ts
   // Before (1.8.1)                                 // After (2.0.0)
   lifecycle: { issuesOtp: { challengeId, mobile_masked } }
                                                     effects: [{ type: "otp_issued" }]
                                                     // (payload was never read by the runner —
                                                     //  keep challenge details in resultBody
                                                     //  and/or a merge_flow_data effect)
   lifecycle: { clearAwaitingInput: true }           effects: [{ type: "clear_awaiting_input" }]
   lifecycle: { abortFlow: true }                    effects: [{ type: "abort_flow" }]
   flowData: { challengeId, ... }                    effects: [{ type: "merge_flow_data",
                                                                 data: { challengeId, ... } }]
   ```
2. **`stateUpdate` is domain-only.** Writing a library-managed slot (`awaitingInput`, `currentFlow`,
   `boundedChoice`, `pagedRead`, `handoff`, `errorCount`) through `stateUpdate` now THROWS. An
   executor-requested terminal handoff becomes
   `effects: [{ type: "request_handoff", request: { reason, context } }]` — and unlike the 1.x slot
   write, it applies the SAME atomic cleanup as the built-in `request_handoff` action (clears
   `awaitingInput` / `currentFlow` / `boundedChoice` / `pagedRead`), and enforces handoff
   monotonicity (the batch ends after the current step).
3. **`stateAnnotation` option deleted** (deprecated alias since 1.7.0) — pass `stateSchema`
   (accepts the same `Annotation.Root` or Zod object).
4. **`ConfirmationOpts.ttlMs` deleted** (was accepted-but-inert; the runner never timed anything
   out). Remove it from configs.
5. **`OtpOpts` deleted** (was an empty placeholder; never exported). `requiresOtp` is plain
   `boolean`.
6. **Stricter construction-time validation.** `startsMatchFor` requires the consumer to exist AND
   declare `requiresMatch`; `issuesOtp.consumer_action` and `requiresMatch.capturer` must name
   existing actions; and the state schema must have a channel for every library slot the
   configuration writes. Previously these surfaced as runtime throws mid-conversation (or silently
   dropped writes).
7. **Confirmation turn-provenance (hardening).** Proposals are stamped with the caller-turn
   identity (`proposed_on_caller_turn_id`); a matching re-call on the SAME caller turn is refused
   (`confirmation_same_turn_locked`) without spending an attempt. Enforced only when both turn
   identities exist — identity-less direct `runSteps` fixtures keep params-only behavior. **Tests
   that drive propose → execute by hand and whose fixture states carry message ids must simulate
   the caller's answering turn between the two calls.**
8. **Import paths for non-index imports.** `handoff.js` split into `handoff/contract.js`
   (action + signals + `HandoffSpec`), `handoff/node.js` (`createHandoffNode`), and
   `handoff/delegate-client.js` (transport). Projects importing ONLY from `agent-step/index.js`
   (the documented surface) are unaffected — every 1.x index export except the deleted items above
   is still there.

Additive (no action required, available to adopt): `boundedChoices` +
`request_bounded_choice`/`resolve_bounded_choice` controls with the `boundedChoice` state slot;
`getCallerTurnId`; the `ExecutorEffect` export; abort-aware planning; canonical value-equality
hardening.

## Why

One 2,268-line `runner.ts` became phase modules with explicit contracts (`compile/`, `run/`,
`interaction/`, `controls/`, `handoff/`), making every gate's lockdown/attempts/freshness/clearing
rules readable in one place and letting a new library-owned control be added without touching the
runner. The effects reshape closes the two loopholes the 1.x contract left open — an executor could
write library slots through `stateUpdate` (bypassing the gates' invariants), and the `lifecycle`
payload shape implied the runner consumed data it never read. The turn-provenance guards close a
voice-channel safety gap: a model confirming its own proposal (or resolving its own offered choice)
within a single caller turn.

## Library replacement

`/pull-library` replaces `src/agent-step/` wholesale (verbatim copy from the toolkit — note the
copy is now RECURSIVE: five subdirectories plus the top-level files; delete the old flat
`handoff.ts` if the tooling didn't already). A 1.x project will NOT compile until the transforms
below are applied — apply them immediately after the copy, then typecheck.

<transforms>

   change: Rewrite the `ExecutorResult` returns to the `effects` array —
     `lifecycle: { issuesOtp: {...} }` → add `{ type: "otp_issued" }` and move the challenge

## Manual follow-ups

1. **Consider adopting the bounded-choice overlay.** If the agent has a spoken fork the prompt
   currently improvises around (e.g. "do you want to continue with the alternative, or stop?"),
   `boundedChoices` gives it engine-owned one-shot semantics with lockdown and turn locks. This is
   a design decision (which choices, which `directInputActions`, the prompt section that offers
   it) — not automatable. See the toolkit's `agent-step-api.md` `<bounded_choice>`.
2. **Hosts that compact or replace messages MUST provide `getCallerTurnId`.** The turn guards key
   on the latest human message id by default; if the host rewrites history (summarization,
   compaction), supply a stable turn token or the confirmation same-turn lock may misfire. Hosts
   with vanilla message accumulation need nothing.
3. **Construction now fails earlier.** A misconfigured tool that used to limp until a specific
   conversation path now throws at startup (cross-action pairs, channel completeness). If a deploy
   pipeline smoke-tests by importing the graph, expect misconfigs to surface there — that is the
   point.
4. **Auto-handoff `context` unchanged.** The error-counter policy and its messages are 1.8.1's;
   no re-tuning needed.
