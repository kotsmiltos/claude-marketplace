# Migrate agent-step 2.5.0 → 3.0.0

> Severity: **breaking**. Applied by `/pull-library`; readable standalone.

## What changed

3.0.0 makes the authoring model declarative and moves the model-facing language into the engine:

1. **Executors return declared verdicts.** The legacy `ExecutorResult` shape
   (`{ resultBody, ok, stateUpdate?, effects? }`) is gone from the public contract. Every outcome is
   a row in `ActionDef.verdicts` (`VerdictDef`: `ok` flag, summary — static or a `(state, data)`
   renderer —, body fields in declaration order, static `stateUpdate`, row `effects`,
   `backendFailure`), and the executor returns `DeclaredExecutorResult`:

   ```ts
   // before (2.5.0)
   return {
     resultBody: { summary: "Card status change persisted; new state: " + postState + ".",
                   success: true, preState, postState },
     ok: true,
   };

   // after (3.0.0) — action.ts declares:
   //   verdicts: { ok: { ok: true,
   //     summary: (_s, d) => `Card status change persisted; new state: ${d.postState}.`,
   //     body: { success: true } } }
   return { verdict: "ok", data: { postState }, resultExtras: { preState, postState } };
   ```

   Declaration order is wire order — a converted action reproduces its historical body bytes exactly.
2. **The engine composes the model surface.** Action descriptions are
   `<gate marker> <host semantic lead>` (no verdict index); proposals carry a `reply_contract`
   (generic template, or an action-specific one composed from `ConfirmationOpts.replyContract`, a
   `GateContractSpec`); `composeProtocolPrompt` renders the whole machinery prompt fragment hosts
   splice at `{PROTOCOL}`; `readBackDirective` frames the read-back on the wire.
3. **Standing asks.** `ActionDef.asks` maps verdict-or-error codes to a `dictation` awaiting record
   (non-locking); the final entry is stamped `standing_ask` / `ask_contract` / `ask_text`.
4. **Ladders.** `BuildAgentStepToolOptions.ladders` + the sole-step `note_refusal` control absorb
   the prompt's "once" rules into the task-scoped `spentLadders` latch; `captureBounces` bounds
   consecutive `invalid_params` re-asks through a named ladder.
5. **Removals.** The bounded-choice subsystem, the `deflect_aside` control, the `guardTurn` guard
   latch, and the `forcedHandoff` state-predicate net are gone (zero-host or superseded); the
   repeat control renamed `repeat_pending_confirmation` → `repeat_pending_question`; library state
   is six slots (`awaitingInput`, `currentFlow`, `pagedRead`, `spentLadders`, `handoff`,
   `errorCount`).

## Why

Measured on the reference voice host: hand-kept executor bodies forked from their doctrine; every
host restated the gate handshake and machinery prompt (and the copies drifted); the model improvised
re-asks past ~3 identical capture bounces (uncounted, so nothing could escalate); fixed asks recited
from prompt memory decorated the catalog line (2/8 vs 8/8 on the wire); and the prompt's "once"
counters asked the model to count from history. One authority per sentence, with the engine owning
what it enforces.

## Library replacement

The vendored `src/agent-step/*` is replaced wholesale by `/pull-library` (verbatim copy from the
toolkit). No per-file action needed — this section just records what moved: added
`compile/{action-describe,gate-contract,protocol,activation}.ts`, `controls/note-refusal.ts`,
`interaction/{dictation,turn-identity}.ts`; renamed `controls/repeat-confirmation.ts` →
`repeat-question.ts`; removed `interaction/bounded-choice.ts`, `interaction/guard-latch.ts`,
`controls/bounded-choice.ts`, `controls/deflect-aside.ts` (+ their test files; new test files per
the CHANGELOG).

## Manual follow-ups

- **Wire/model goldens re-measure.** Composed bytes moved (descriptions, contracts, the protocol
  fragment): regenerate the model-surface and wire-text goldens deliberately and re-run the
  project's prompt-input suite live. For the reference host the port lands as a no-op
  (byte-identical goldens); every other host owes its own measurement.
- **Live checkpointed threads.** Old `boundedChoice` / `deflectedAside` / `guardTurn` channel values
  in persisted threads are simply ignored after the upgrade (their channels disappear from the
  schema); a choice pending mid-call at deploy time is lost — drain or accept.
- **Optional adoptions** (recommended, not required): `ActionDef.asks` + `DictationAsk.render` for
  every recoverable capture miss; `captureBounces: { max: 2, ladder }` on dictated-capture actions;
  ladders for any remaining prompt "once" rules; `readBackDirective` where the recap needs explicit
  framing; a localized `standing_ask_contract` override if the host tightens the generic taxonomy.
- **Message overrides.** Hosts overriding `messages` should adopt the new keys
  (`confirm_reply_contract`, `standing_ask_contract`, `read_back_directive_repeat`) only if they
  need non-default taxonomy — the defaults are model-facing English and correct for any language
  host; choice-related overrides (`choice_reply_contract`, the two choice directives,
  `aside_deflected`) have no effect and should be deleted.
