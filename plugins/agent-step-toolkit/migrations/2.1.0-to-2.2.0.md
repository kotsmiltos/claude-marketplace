# Migrate agent-step 2.1.0 → 2.2.0

> Severity: additive (with one behavior change). Applied by `/pull-library`; readable standalone.

## What changed

**`createHandoffNode` now clears task-scoped state when a task ENDS.** Nothing is removed or
reshaped: one new export, one new optional `HandoffSpec` field, no signature touched.

- `agentStepTaskScopedSlots` (new export) — the library slots that describe work in progress:
  `awaitingInput`, `currentFlow`, `boundedChoice`, `pagedRead`, `errorCount`. `handoff` is
  deliberately absent (the node returns it as null either way).
- `HandoffSpec.clearsOnHandback?: readonly (keyof T & string)[]` (new, optional) — host DOMAIN slots
  to null alongside them.
- On `completed` / `abandon` in terminate mode, the node returns
  `{ handoff: null, ...clears, messages: [AIMessage] }`. **`off_topic` clears nothing** — a mid-task
  aside must stay resumable — and **a successful delegate clears nothing**, because the conversation
  never left this agent. Both carve-outs are correctness invariants, not options.

## Why

The THREAD outlives the TASK. A channel middleware reuses one thread id for an entire call and never
resets it on re-dispatch, so whatever sits in state when a handback resolves is what the NEXT task on
that thread starts from. Pending gates were the visible half — a stale `awaitingInput` locking down
the next task's first batch. The damaging half was host-side: a graph that derives a forced handback
or escalation from a terminal domain slot ("this task already finished / already active") re-derives
it on every later turn of the same call, so the caller is bounced turn after turn with no way out.
Clearing at the moment the task ends is the only place that fixes both, because it is the only point
that knows the task ended rather than paused.

## Library replacement

The vendored `src/agent-step/*` is replaced wholesale by `/pull-library` (verbatim copy from the
toolkit; recursive). No files were added or removed in this version. The suite grows 168 → 173 (five
handoff tests covering both task-ending signals, the `off_topic` carve-out, and the delegate case).

Projects that declare no `clearsOnHandback` still get the library-slot clearing — that half needs no
project change.

<transforms>
1. id: declare-terminal-domain-slots
   target: OPTIONAL but RECOMMENDED — the `HandoffSpec` object the host passes to
     `createHandoffNode` (typically in the graph module, e.g. `src/graph.ts`, or a
     `src/handoff-spec.ts` sibling).
   change: Identify host state slots that record a TERMINAL outcome for ONE task — anything the
     graph, prompt, or a verifier reads to mean "this task is finished / already handled /
     escalated", plus any pointer slot naming the entity that task operated on. Add them to
     `clearsOnHandback: [...]`. Do NOT list slots that carry caller identity or session context
     that legitimately spans tasks within one call (a verified customer, the caller's language),
     and do NOT list slots whose reducer MERGES rather than replaces — the write is a plain `null`;
     reset those through the pointer slot that selects from them instead.
   example: |
     const spec: HandoffSpec<AgentState> = {
       offTopic: { mode: "terminate" },
       terminateMessage: "…",
       resolveClosingMessage: (s, r) => …,
     + clearsOnHandback: ["activationOutcome", "selectedCard"],
     };
   check: `npm run typecheck` passes (each listed key must exist on the state type, be nullable, and
     not be `messages`); a two-task sandbox run on ONE thread — drive a task to a `completed`
     handback, then start a second task on the same thread — shows the second task starting clean
     rather than re-firing the first task's closing.
</transforms>

## Manual follow-ups

1. **Re-check any graph edge or prompt section that reads a terminal slot.** If such a branch existed
   as a workaround for state leaking across tasks (e.g. a guard that ignores the outcome slot when
   the turn looks like a fresh request), it is now redundant and should be removed — leaving both can
   mask a slot you forgot to declare.
2. **Slots with merging reducers** cannot be cleared by this mechanism. If one holds task-scoped data,
   either give the pointer slot that selects from it a place in `clearsOnHandback`, or reset the map
   explicitly in the executor that ends the task.
3. **No middleware change is required.** The thread-reuse behavior this fixes is the middleware's
   existing, correct behavior; the library now accounts for it.
