# Migrate agent-step 1.6.0 → 1.7.0

> Severity: additive (library) + contract shift (tool-authoring). Applied by `/pull-library`;
> readable standalone.

## What changed

A **Zod state schema is now a first-class alternative to a LangGraph `Annotation.Root`.** The runner
derives its intra-batch merger from either form, so a project can define graph state **once** in Zod
(gaining invoke-boundary validation/coercion) instead of maintaining a parallel Annotation + Zod pair.

Library surface (all additive — nothing removed or signature-broken):

- **New `buildAgentStepTool` option `stateSchema`** (`BuildAgentStepToolOptions.stateSchema`):
  ```ts
  stateSchema?: StateSchemaLike;   // LangGraphAnnotationLike | z.ZodObject
  ```
  It accepts **either** an `Annotation.Root` **or** a Zod object whose fields carry reducer/default
  metadata via `withLangGraph` (`@langchain/langgraph/zod`). Both resolve to the same channel classes
  (`BinaryOperatorAggregate` / `LastValue`), so the merger reads `.operator` off either uniformly.
- **`stateAnnotation` is now a deprecated alias** of `stateSchema` (still accepted; the runner reads
  whichever is set). The runner **throws at construction** if neither is provided.
- **New exports** from `index.ts`: `StateSchemaLike` (type) and **`agentStepInternalSlotMask`** — a
  Zod `.omit()` mask of the five library-managed slot keys, for deriving a graph INPUT schema.
- **`agentStepZodShape` slots are now `withLangGraph`-wrapped**, so spreading the fragment into a Zod
  state schema gives each library slot its real last-writer-wins reducer + default as channel
  metadata (previously the Zod fragment carried only `.nullable().optional().default(null)`, i.e.
  `LastValue` with no registered reducer).
- New isolation test `zod-state.test.ts` (the merger reads reducers off a Zod schema).

```ts
// Before (1.6.0): Annotation is the canonical state; a parallel Zod schema duplicates it.
export const AgentState = Annotation.Root({ ...MessagesAnnotation.spec, ...agentStepStateSpec, /*…*/ });
export type State = typeof AgentState.State;
buildAgentStepTool({ config, stateAnnotation: AgentState, /*…*/ });

// After (1.7.0): one Zod schema is the single source of truth for reducers AND validation.
export const AgentStateSchema = MessagesZodState.extend({ ...agentStepZodShape, /* domain slots via withLangGraph */ });
export type State = ExtractStateType<typeof AgentStateSchema>;
export const AgentInputSchema = AgentStateSchema.omit({ ...agentStepInternalSlotMask, /*…*/ }).partial();
buildAgentStepTool({ config, stateSchema: AgentStateSchema, /*…*/ });
```

## Why

Projects were maintaining state twice — a `Annotation.Root` for the graph + runner reducers AND a
parallel Zod `AgentStateSchema` for `createReactAgent`/validation — and the two drifted (identity
reducers defined on the Annotation never took effect when the graph was built from the Zod schema's
plain `LastValue` fields). Collapsing to one Zod schema removes the drift and unlocks **invoke-boundary
validation**: a hand-built `new StateGraph({ state, input })` rejects a malformed or
internal-slot-injecting invoke at the boundary and coerces typed fields (e.g. an unquoted JSON number
→ string via `z.coerce.string()`), instead of letting a wrong-typed value crash a downstream consumer.

## Library replacement

`/pull-library` replaces `src/agent-step/*` wholesale (verbatim copy from the toolkit), including the
new `zod-state.test.ts`. Because `stateAnnotation` is still accepted, a project that applies NO
transforms keeps compiling on the new runner. The transforms below adopt the recommended single-Zod
pattern — apply them so the project teaches/uses only the latest contract.

<transforms>
1. id: consolidate-state-to-single-zod-schema
   target: `src/state.ts`
   change: Collapse the dual definition into ONE Zod schema. If the file declares a LangGraph
     `AgentState = Annotation.Root({ ...MessagesAnnotation.spec, ...agentStepStateSpec, <domain> })`
     AND a separate `AgentStateSchema = MessagesZodState.extend({ ...agentStepZodShape, <domain> })`,
     KEEP the Zod `AgentStateSchema` and DELETE the Annotation. Spread `agentStepZodShape` for the
     library-managed slots. For every domain slot, carry its reducer/default via `withLangGraph`
     (import from `@langchain/langgraph/zod`) instead of `Annotation<T>({ reducer, default })` or a
     plain `.optional().default()`. `withLangGraph` field shape: supply the channel default via the
     meta `default` (NOT a zod `.default()`), and use plain `.nullable()` on the field (NOT
     `.optional()`/`.default()`, which widen the input type with `undefined`). Replace
     `export type State = typeof AgentState.State` with
     `export type State = ExtractStateType<typeof AgentStateSchema>` (import `ExtractStateType` and

     `MessagesAnnotation` / `agentStepStateSpec` imports.

     - activeAccountNumber: Annotation<string | null>({ reducer: (_, n) => n ?? null, default: () => null }),

     +   reducer: { fn: (_prev: string | null, next: string | null) => next ?? null },

     + }),
   check: `grep -n "Annotation.Root\|typeof AgentState.State\|agentStepStateSpec" src/state.ts`

     - import { AgentState, type State } from "../../state.js";
     + import { AgentStateSchema, type State } from "../../state.js";
       buildAgentStepTool({ config, stateSchema: AgentStateSchema, selectors, executors, verifiers });

   target: any file that declared a local `type State = typeof AgentState.State` (executors,
     verifiers, selectors, `prompt.ts`, test `_setup.ts`)
   change: Delete the local alias and instead `import type { State } from "<relative>/state.js"`
     (`State` is now exported from `state.ts`). Update any `import type { AgentState }` to
     `import type { State }`.
   check: `grep -rn "typeof AgentState.State" src` returns nothing; typecheck passes.

5. id: wire-input-schema-into-stategraph
   target: `src/agent.ts` (ONLY if the project hand-builds its graph with `StateGraph`)
   change: If the graph is `new StateGraph(AgentState)` (single annotation arg), change it to
     `new StateGraph({ state: AgentStateSchema, input: AgentInputSchema })` to gain invoke-boundary
     validation/coercion. If the graph uses `createReactAgent`, leave `stateSchema: AgentStateSchema`
     as-is — `createReactAgent` takes no separate `input` schema, so `AgentInputSchema` stays exported
     but unwired until the project graduates to a hand-built `StateGraph`. Do NOT convert
     `createReactAgent` to `StateGraph` as part of this migration.
   check: typecheck passes; for the `StateGraph` case, a wrong-typed invoke field is rejected with a
     `StateGraphInputError` (or coerced if the field uses `z.coerce.*`).

## Manual follow-ups

1. **Boundary coercion is opt-in per field.** To coerce a caller-supplied field at the invoke
   boundary (e.g. a phone number typed unquoted in LangGraph Studio arriving as a JSON number), use
   `z.coerce.string().nullable()` on that slot in `AgentStateSchema`. This only takes effect once
   `AgentInputSchema` is wired into a hand-built `StateGraph` (transform 5) — `createReactAgent`
   projects keep the value as-received.
2. **`createReactAgent` cannot validate input at the boundary.** It accepts `stateSchema` but no
   separate `input` schema. If invoke-boundary validation / a typed Studio input form matters, plan
   the graduation to `new StateGraph({ state, input })` (out of scope for this migration).
3. **`withLangGraph` field-shape gotcha.** A slot that needs a default must supply it via the meta
   `default` and keep its zod type as plain `.nullable()`; do NOT use `.optional()` / `.default()` on
   the field itself (they widen the input type with `undefined` and `withLangGraph` rejects the
   mismatch).
4. **Peer dependency.** The 1.7.0 runner unconditionally imports `schemaMetaRegistry` from
   `@langchain/langgraph/zod` (the zod-state mechanism behind `withLangGraph`). The bootstrap
   scaffold's pin (`@langchain/langgraph` `~1.3`) ships it; a project pinned to an older
   `@langchain/langgraph` will fail typecheck on that import right after the pull — upgrade the
   package (and re-run the project's tests) before applying the transforms.
